# Веб-интерфейс сканера файлов

Страница в браузере, которая показывает результаты `main.py`: когда был последний скан и что в нём нашли.
Только читает БД, ничего в ней не меняет.

    cron / Планировщик → main.py → PostgreSQL ← web/app.py ← браузер руководителя

## Устройство (для объяснения)

| Файл                   | Что делает |
|------------------------|------------|
| `app.py`               | сервер на Flask: 3 адреса (`/`, `/scans/N`, `/files/N`). Каждый делает SELECT в PostgreSQL и отдаёт HTML |
| `templates/*.html`     | HTML-шаблоны (Jinja2): в них подставляются данные из запроса |
| `requirements.txt`     | нужные библиотеки: Flask (сайт), psycopg2 (связь с PostgreSQL) |

Страницы: **Сканирования** (статус «сканер работает / давно не запускался» + история), **Скан №N** (новые / изменённые /
удалённые файлы), **карточка файла** (свойства и извлечённый текст).

## Запуск на этом же компьютере (где БД)

    cd web
    pip install -r requirements.txt
    python app.py

Открыть http://127.0.0.1:8000

## Запуск на другом компьютере

Нужно: Python 3.10+ (при установке на Windows отметить «Add Python to PATH») и сетевая связь с БД.
Два варианта.

### Вариант A. База остаётся на старом компьютере, веб запускаем на новом

**1. Разрешить подключение к БД по сети** (на компьютере с PostgreSQL).
По умолчанию PostgreSQL принимает только локальные подключения.

- `postgresql.conf`: `listen_addresses = '*'`
- `pg_hba.conf` - добавить строку (подсеть замените на свою):
  `host  file_storage  viewer  192.168.1.0/24  scram-sha-256`
- перезапустить службу PostgreSQL;
- открыть порт 5432 в брандмауэре Windows (Входящие правила → TCP 5432).

Отдельный пользователь только на чтение (безопаснее, чем `postgres`):

    CREATE USER viewer WITH PASSWORD 'придумайте_пароль';
    GRANT CONNECT ON DATABASE file_storage TO viewer;
    GRANT USAGE ON SCHEMA public TO viewer;
    GRANT SELECT ON scans, paths, files, json TO viewer;

**2. Скопировать папку `web` на новый компьютер и поставить библиотеки:**

    cd web
    pip install -r requirements.txt

**3. Указать, где БД, и запустить** (IP - адрес компьютера с PostgreSQL):

    Windows (cmd):   set DB_DSN=host=192.168.1.10 port=5432 dbname=file_storage user=viewer password=ПАРОЛЬ
                     python app.py
    Linux:           DB_DSN="host=192.168.1.10 port=5432 dbname=file_storage user=viewer password=ПАРОЛЬ" python3 app.py

**4. Открыть доступ к сайту для других** - разрешить входящий TCP 8000:

    netsh advfirewall firewall add rule name="Scanner Web" dir=in action=allow protocol=TCP localport=8000

**5. Узнать IP нового компьютера** (`ipconfig` в Windows, `hostname -I` в Linux) и дать руководителям ссылку
`http://<этот IP>:8000`.

### Вариант B. Переезжает всё (БД + сканер + веб) на новый компьютер

1. Установить PostgreSQL и Python.
2. Перенести базу. На старом: `pg_dump -U postgres file_storage > backup.sql`.
   На новом: `createdb -U postgres file_storage`, затем `psql -U postgres -d file_storage -f backup.sql`.
   (Или создать пустую базу скриптом `create_tables.sql` - тогда история сканов начнётся заново.)
3. В `main.py` поправить `ROOT_PATH` (какую папку сканировать) и при необходимости `DB_DSN`.
4. Далее как «Запуск на этом же компьютере». Порт 8000 открыть так же, как в шаге 4 варианта A.

## Чтобы сайт работал постоянно

`python app.py` работает, пока открыто окно. Для постоянной работы:

- **Windows:** Планировщик заданий → «Создать задачу» → триггер «При запуске компьютера» → действие
  «Запуск программы» `python`, аргумент `app.py`, «Рабочая папка» - папка `web`.
- **Linux:** создать службу systemd с `ExecStart=/usr/bin/python3 /путь/web/app.py`.

## Если сайт не открывается

| Что видно                                        | Причина |
|--------------------------------------------------|---------|
| «Не удаётся получить доступ» с другого компьютера | закрыт порт 8000 (шаг 4) или сайт запущен с `WEB_HOST=127.0.0.1` |
| Страница с ошибкой 500 в логе `connection refused` | PostgreSQL недоступен: неверный IP в `DB_DSN`, не открыт 5432, не настроен `pg_hba.conf` |
| `password authentication failed`                 | неверный пользователь или пароль в `DB_DSN` |
| `ModuleNotFoundError: flask`                     | не выполнено `pip install -r requirements.txt` |

## Настройки (переменные окружения, все необязательные)

`DB_DSN` - подключение к БД · `WEB_PORT` - порт (8000) · `WEB_HOST` - `0.0.0.0` (по сети) или `127.0.0.1` (только этот
компьютер) · `STALE_HOURS` - через сколько часов без скана показывать красное предупреждение (26).

## Важно знать

- Авторизации нет, а на страницах виден текст документов - открывать только во внутренней сети.
- В расписании запускайте сканер из папки проекта (`cd /путь/проекта && python main.py`): `snapshot.json`
  хранится по относительному пути.
- Скан, упавший с ошибкой, в БД не виден (транзакция откатывается) - ошибки смотрите в логе запуска.
  Красная плашка на главной покажет, что давно не было новых сканов.
