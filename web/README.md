# Веб-интерфейс сканера файлов

Страница в браузере: показывает результаты сканера, строит отчёты и **запускает сканирование выбранной папки**.

    cron / Планировщик ─┐
    кнопка на сайте  ───┴→ main.py → PostgreSQL ← web/app.py ← браузер руководителя

Сайт только читает БД (SELECT). Записывает в БД только сам сканер `main.py`, который сайт запускает отдельным процессом.

## Устройство (для объяснения)

| Файл                   | Что делает |
|------------------------|------------|
| `app.py`               | сервер на Flask: страницы, обзор папок (`/api/fs`), запуск сканера (`/run/...`), отчёты (`/reports/...`) |
| `reports.py`           | отчёты: для каждого - SELECT в PostgreSQL + описание колонок; также выгрузка в CSV |
| `templates/*.html`     | HTML-шаблоны (Jinja2): `report.html` рисует любой отчёт, `run.html` - страница запуска скана |
| `static/style.css`, `static/run.js` | оформление; скрипт страницы запуска (обзор папок, ход сканирования) |
| `requirements.txt`     | нужные библиотеки: Flask (сайт), psycopg2 (связь с PostgreSQL) |

Страницы: **Сканирования** (статус «сканер работает / давно не запускался» + история), **Запуск скана** (выбор папки и
запуск), **Отчёты**, **Поиск файлов** (по имени и по тексту внутри), **Скан №N** (новые / изменённые / удалённые файлы),
**карточка файла**.

## История сканов

Страница «Скан №N» показывает файлы, которые были новыми / изменёнными / удалёнными **именно в этом скане** - история
хранится в таблице `scan_files`. Сканер создаёт её сам при первом запуске новой версии. Если сайт подключается пользователем
`viewer`, выдайте ему право чтения: `GRANT SELECT ON scan_files TO viewer;`. Сканы, сделанные до обновления, остаются с
неполными списками (в старой схеме эти данные не сохранялись), числа во вкладках у них точные.

## Запуск скана из браузера

Вкладка **Запуск скана**: введите путь или нажмите **«Обзор…»**, выберите папку в списке и нажмите **«Сканировать»**.
Видно ход выполнения (сколько файлов обработано, лог сканера), кнопка **«Остановить»** отменяет скан - при этом в БД
ничего не записывается. Одновременно идёт только один скан.

- Папка выбирается **на компьютере, где запущен сайт** (браузер не может передать серверу путь со своего компьютера).
  Для сканирования сетевой папки укажите её путь, видимый серверу (`\\server\share` или диск, подключённый на сервере).
- Сайт запускает `python main.py <папка>` из папки проекта. Нужны библиотеки сканера: `pip install -r ../requirements.txt`.
  Если сайт работает в другом окружении Python - задайте `SCANNER_PYTHON` (путь к `python`), где они установлены.
- Снимок `snapshot.json` общий для всех папок и лежит рядом с `main.py`; статусы «новый / изменён / удалён» считаются
  только внутри выбранной папки, поэтому скан одной папки не помечает удалёнными файлы другой.
- Сайт может подключаться к БД пользователем `viewer` (только чтение), а сканеру нужны права записи - для него
  задайте отдельное подключение `SCANNER_DB_DSN` (если не задано, используется `DB_DSN`).

## Отчёты

Вкладка **Отчёты**. Папку скана можно выбрать в выпадающем списке (или смотреть «Все папки»), у каждого отчёта есть
настройки (период, число строк) и кнопка **«Скачать CSV»** (открывается в Excel).

| Отчёт | Что показывает и зачем |
|-------|------------------------|
| Сводка | Файлов, размер, дубликаты, файлы без текста + подсказки, куда смотреть дальше |
| Дубликаты | Файлы с одинаковым MD5 и сколько места можно освободить |
| Крупнейшие файлы | Топ файлов по размеру и их доля от объёма |
| По типам файлов | Сколько места занимает каждый тип (расширение) |
| По папкам | Размер папок первого уровня внутри выбранной папки скана |
| Изменения | Динамика по сканам, изменённые за период, часто меняющиеся, удалённые файлы |
| Устаревшие файлы | Не менялись дольше выбранного срока - кандидаты на архив |
| Файлы без текста | Что сканер не смог прочитать и поэтому не находится поиском по содержимому |

## Запуск на этом же компьютере (где БД)

    cd web
    pip install -r requirements.txt
    python app.py

Открыть http://127.0.0.1:8000

## Запуск на другом компьютере

Нужно: Python 3.10+ (при установке на Windows отметить «Add Python to PATH») и сетевая связь с БД.
Два варианта.

### Вариант A. База остаётся на старом компьютере, веб запускаем на новом

**1. Разрешить подключение к БД по сети** (на компьютере с PostgreSQL).
По умолчанию PostgreSQL принимает только локальные подключения.

- `postgresql.conf`: `listen_addresses = '*'`
- `pg_hba.conf` - добавить строку (подсеть замените на свою):
  `host  file_storage  viewer  192.168.1.0/24  scram-sha-256`
- перезапустить службу PostgreSQL;
- открыть порт 5432 в брандмауэре Windows (Входящие правила → TCP 5432).

Отдельный пользователь только на чтение (безопаснее, чем `postgres`):

    CREATE USER viewer WITH PASSWORD 'придумайте_пароль';
    GRANT CONNECT ON DATABASE file_storage TO viewer;
    GRANT USAGE ON SCHEMA public TO viewer;
    GRANT SELECT ON scans, paths, files, json, scan_files TO viewer;

**2. Скопировать папку `web` на новый компьютер и поставить библиотеки:**

    cd web
    pip install -r requirements.txt

**3. Указать, где БД, и запустить** (IP - адрес компьютера с PostgreSQL):

    Windows (cmd):   set DB_DSN=host=192.168.1.10 port=5432 dbname=file_storage user=viewer password=ПАРОЛЬ
                     python app.py
    Linux:           DB_DSN="host=192.168.1.10 port=5432 dbname=file_storage user=viewer password=ПАРОЛЬ" python3 app.py

**4. Открыть доступ к сайту для других** - разрешить входящий TCP 8000:

    netsh advfirewall firewall add rule name="Scanner Web" dir=in action=allow protocol=TCP localport=8000

**5. Узнать IP нового компьютера** (`ipconfig` в Windows, `hostname -I` в Linux) и дать руководителям ссылку
`http://<этот IP>:8000`.

### Вариант B. Переезжает всё (БД + сканер + веб) на новый компьютер

1. Установить PostgreSQL и Python.
2. Перенести базу. На старом: `pg_dump -U postgres file_storage > backup.sql`.
   На новом: `createdb -U postgres file_storage`, затем `psql -U postgres -d file_storage -f backup.sql`.
   (Или создать пустую базу скриптом `create_tables.sql` - тогда история сканов начнётся заново.)
3. В `main.py` поправить `ROOT_PATH` (какую папку сканировать) и при необходимости `DB_DSN`.
4. Далее как «Запуск на этом же компьютере». Порт 8000 открыть так же, как в шаге 4 варианта A.

## Чтобы сайт работал постоянно

`python app.py` работает, пока открыто окно. Для постоянной работы:

- **Windows:** Планировщик заданий → «Создать задачу» → триггер «При запуске компьютера» → действие
  «Запуск программы» `python`, аргумент `app.py`, «Рабочая папка» - папка `web`.
- **Linux:** создать службу systemd с `ExecStart=/usr/bin/python3 /путь/web/app.py`.

## Если сайт не открывается

| Что видно                                        | Причина |
|--------------------------------------------------|---------|
| «Не удаётся получить доступ» с другого компьютера | закрыт порт 8000 (шаг 4) или сайт запущен с `WEB_HOST=127.0.0.1` |
| Страница с ошибкой 500 в логе `connection refused` | PostgreSQL недоступен: неверный IP в `DB_DSN`, не открыт 5432, не настроен `pg_hba.conf` |
| `password authentication failed`                 | неверный пользователь или пароль в `DB_DSN` |
| `ModuleNotFoundError: flask`                     | не выполнено `pip install -r requirements.txt` |
| Скан из браузера: «завершился с ошибкой», в логе `No module named ...` | для `python`, которым запущен сайт, не установлены библиотеки сканера: `pip install -r ../requirements.txt` или задайте `SCANNER_PYTHON` |
| Скан из браузера: в логе `permission denied` / `password authentication failed` | у пользователя БД нет прав на запись: задайте `SCANNER_DB_DSN` |

## Настройки (переменные окружения, все необязательные)

`DB_DSN` - подключение к БД · `WEB_PORT` - порт (8000) · `WEB_HOST` - `0.0.0.0` (по сети) или `127.0.0.1` (только этот
компьютер) · `STALE_HOURS` - через сколько часов без скана показывать красное предупреждение (26) · `OPEN_BROWSER` - `0`, чтобы сайт не открывал браузер при запуске.

Для запуска сканера из браузера: `SCANNER_DB_DSN` - подключение к БД для сканера (по умолчанию `DB_DSN`) ·
`SCANNER_PYTHON` - какой `python` запускает `main.py` (по умолчанию тот же, что у сайта) · `SCANNER_DIR` - папка с `main.py`
(по умолчанию на уровень выше `web`) · `SCAN_ALLOWED_ROOTS` - список папок, за пределы которых нельзя выходить при выборе и
сканировании (через `;` в Windows и `:` в Linux; пусто = любые папки), например `D:\Documents;E:\Projects`.

## Важно знать

- Авторизации нет, а на страницах виден текст документов - открывать только во внутренней сети. Теперь любой, кто
  открыл сайт, может запустить скан и **просматривать список папок сервера**: ограничьте доступные папки через
  `SCAN_ALLOWED_ROOTS` и не открывайте сайт за пределы доверенной сети.
- Сканер можно запускать и по расписанию: `python main.py` (папка из `ROOT_PATH` в `main.py`) или
  `python main.py "D:\Документы"` / переменная `SCAN_ROOT`. Снимок `snapshot.json` хранится рядом с `main.py`,
  поэтому запуск из любой папки использует один и тот же файл.
- Скан, упавший с ошибкой, в БД не виден (транзакция откатывается) - ошибки смотрите в логе запуска.
  Красная плашка на главной покажет, что давно не было новых сканов.
